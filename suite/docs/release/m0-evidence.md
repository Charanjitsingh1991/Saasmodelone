# M0 evidence

Date: 22 October 2026
Status: **interim evidence pack — M0 has not exited**

This document records what the current tree proves, what it merely checks structurally, and what remains unproven. It is not a release approval and not a claim that the product is ready for customer data. The signed-in shell now demonstrates the last functional M0 exit criterion in a local browser, but M0 has not exited: the Postgres outbox has its claim helpers, dedicated `saas_worker` role and polling loop, yet no producer writes an event, no production handler is registered and no worker process is deployed, so no event moves on a real system; the restore drill is executed only as a manual local logical dump and restore, never on a schedule; CI and PostgreSQL 16 have never run; the draft threat model has not been reviewed by a named human security owner; and the design-partner gate in [`../security.md`](../security.md) is still unticked.

## 7. Not proven — do not claim

Do not claim any of the following on the strength of this tree:

- That the Postgres outbox delivers a real business event anywhere. No producer inserts a `domain_event` row, `domain_event` is empty on a migrated, seeded and provisioned database, no production handler is registered and no worker process is deployed or started by any command in this repository.
- That outbox delivery is exactly-once. It is at-least-once by design: handlers must be idempotent, and only the test handlers are.
- That the outbox helpers or `saas_worker` were reviewed by anyone other than their author, or that concurrent workers, queue depth, starvation, purge and dead-letter handling are proven.
- That M0 has exited, or that the product is production-ready.
- That PostgreSQL 16 works. The matrix is authored, not executed.
- That CI passes on GitHub. The workflow contract test is not a CI run.
- That the repository is secret-free. The scanner detects known shapes in tracked and untracked non-ignored regular files only.
- That the threat model is reviewed or approved. It is a draft without a named owner.
- That a backup capability, retention, legal hold, offboarding, full export or audit read exists. The restore drill is one manual logical dump and restore of synthetic local data, not an operational backup.
- That tenant isolation is proven for every table or every future route. The tested runtime surface is `employment`, `project`, the People export and `/v1/context`.
- That the People directory CSV is a complete export or portability feature.
- That role scope, employee self-scope, MFA, session rotation, device lists, distributed rate limiting or authentication-event audit exist.
- That any jurisdiction pack, payroll calculation or statutory output exists.
- That the web shell is deployed, served behind a production reverse proxy or covered by CSP, HSTS or other production security headers. Only the local Vite preview and dev proxy were exercised.
- That People supports data entry, editing, deletion, import, export or any other module screen. The only signed-in screen is the empty People screen and its access state.
- That invitation acceptance, password reset, email delivery, tenant switching or session/device management has a user interface.
- That the UI is accessible beyond the checks listed above. There is no screen-reader, assistive-technology, automated accessibility or visual-regression run.
- That real customer data would be safe in this build. It must not be loaded.
