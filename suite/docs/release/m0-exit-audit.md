Date: 22 October 2026 · Audited source: `2072d05bb0c3eb587dd952f785eb90c44bb0f015` (`feat: add outbox lease helpers and the worker polling loop`), working tree clean at the start of this audit, no Git remote.

Status: **audit only — M0 has not exited and this document does not exit it.**

This is the one place that states, per M0 exit criterion, which test file and which test name proves it and what is still unproven. ## 1. Verdict definitions

| Verdict | Meaning |
| --- | --- |
| proven by test | An automated test in `pnpm test` (or the single Playwright journey, stated as such) asserts the behaviour on a real PostgreSQL database. |
| proven by command | An executed repository command demonstrates it; no test asserts it. |
| partial | Part of the criterion is asserted and part rests on inspection, convention or an adjacent proof. |
| not proven | Nothing in this tree asserts it. |

Every test cited below was executed on `2072d05`; the exact totals are in §6. No claim in this document rests on a mocked database, session or `fetch`.

## 3. Proven locally and repeatably

Anything in this list can be re-executed by a developer on a clean clone with a local PostgreSQL and no network:

No database mock exists anywhere in the suite.
- `pnpm test:e2e` — one Chromium journey through the built shell (the Playwright webServer runs `pnpm build:web` first, so it cannot pass against stale `dist`), disposable database, in-process API.
- `pnpm secret-scan`, `pnpm typecheck`, `pnpm lint`, `pnpm lint:boundaries`, `pnpm audit --prod --audit-level high`, `pnpm build:web`.
- `pnpm db:bootstrap` → `db:migrate` → `db:seed` → `db:provision` → `db:invite` on the local developer database, and `pnpm db:migrate` re-run as a no-op with both grant allowlists reapplied.
- `pnpm drill:restore` — a logical dump and restore into a throwaway database with parity comparison on table count, per-table row counts, RLS-enabled table and policy counts, the exact runtime table and `person` column grants, and a runtime-role query under a set `app.tenant_id`.
- The schema boundary itself: `tests/schema-inventory.test.ts` asserts 66 `tenant_id` tables, 64 with RLS and a permissive `tenant_isolation` policy, exactly `auth_session` and `invitation` without it, `tenant` with RLS and no `tenant_id`, no `relforcerowsecurity` anywhere in `public` or `infra`, the exact runtime grant rows, the eight `person` column grants, and the `saas_worker` surface (zero table and column privileges, exactly eight executable `app` functions, four of them `prosecdef`).

Repeatably does not mean independently reviewed. Nothing in this list has been read by anyone other than its author, and no CI system has executed any of it.

## 4. What has never run anywhere

- **The GitHub Actions workflow.** `.github/workflows/ci.yml` exists and `tests/ci-workflow.test.ts` asserts its triggers, read-only permissions, action allowlist, 10 localhost-only database URLs, four dummy role passwords, the 20-minute timeout, concurrency settings and exact 14-command order. A contract test on a file is not a run. With no Git remote the workflow has never started, no pull request has been gated by it, and no merge has ever been blocked by a red build.
- **The PostgreSQL 16 leg.** CI declares `postgres: ['16', '17']`. Local runs are PostgreSQL 17.9. Nothing in this tree has ever touched 16, so 16 compatibility is unknown, not assumed.
- **The CI browser job.** `pnpm exec playwright install --with-deps chromium` and the journey have only ever run on Windows against a locally downloaded Chromium binary.
- **The restore drill in CI, and any scheduled backup.** `pnpm drill:restore` is a manual command. There is no schedule, no retention policy, no encryption at rest or in transit, no WAL archiving, no point-in-time recovery, no offsite copy, no RPO/RTO verification and no alerting. The target RPO of 15 minutes and RTO of 4 hours in [`../architecture.md`](../architecture.md) have never been measured.
- **The outbox worker as a running thing.** `runOutboxPass` and `startOutboxWorker` are tested against a real queue, but no process starts the loop: there is no CLI entry point, service, cron or supervisor for it, no registered production handler, and no producer inserts a `domain_event` row. `domain_event` was 0 rows in the source database of this audit's restore drill.
- **Any real jurisdiction.** No jurisdiction pack, payroll calculation, statutory report, golden case, local reviewer sign-off or sub-national rule exists. Migrations 0002 and 0005 create payroll and money tables as reviewed structure only.
- **Any production edge, deployment or header set.** No CSP, HSTS, frame-ancestors, referrer policy or proxy-header test exists; only Vite dev and preview proxying to `127.0.0.1:3001` were exercised.
- **Real data.** No customer, payroll, bank or statutory record has ever entered this system, and none should.

## 5. Owner decisions that block M0 exit

None of these four can be performed by a developer agent. Each needs a human decision, an external party, or both. In every case an agent could fabricate the artifact and must not.

| Blocker | Decision needed | Why an agent cannot do it |
| --- | --- | --- |
| A Git remote so CI can execute | Whether to publish this repository, to which host and organization, with what branch protection, and whose credentials authorise the push. | Creating a remote, pushing and enabling Actions changes shared external infrastructure and makes the code public to an org. It has been deliberately withheld: 0 remotes, nothing pushed. An agent choosing a host is a publisher, not a developer. |
| A named human security reviewer | A person must review and approve the 35-threat draft in [`../security/m0-threat-model.md`](../security/m0-threat-model.md), answer its eight review questions, take ownership of the residual risks and sign the T31–T35 outbox helpers, the `saas_worker` grant surface and `0011_outbox.sql`. | A model reviewing its own document adds no assurance — the whole value of the gate is a second human mind. An agent can name itself, which is exactly the fabrication this gate exists to prevent. |
| The design-partner gate | Whether to proceed at all, and with whom: thirteen items in [`../security.md`](../security.md) §11, of which DPA and security schedule, a named security owner and incident contact, production encryption keys, access review, migration rehearsal and a customer-watched rollback/export rehearsal are agreements between people and an external company. | These require a counterparty and contractual signatures. No local command can tick them; ticking them would be a false statement about a real world agreement. |
| The operational backup regime | A decision on provider, region, encryption, retention period, offsite copy, schedule, RPO/RTO target and who is paged when it fails — then someone to operate it. | It runs outside this repository on infrastructure that does not exist yet. An agent can script it, which would look like a backup regime while being nothing of the sort. The executed drill is a one-off logical dump of synthetic local data. |

Also outside an agent's reach, tracked in the same gate: an independent penetration test, a payroll advisor's sign-off on any jurisdiction pack, and the human review of the schema that [`../roadmap.md`](../roadmap.md) lists as "reviewed by a second engineer".

**Consequence:** M0 is not exited and cannot be exited by the next commit. Seven criteria are green, one is partial, and the four blockers above are untouched by any test.
