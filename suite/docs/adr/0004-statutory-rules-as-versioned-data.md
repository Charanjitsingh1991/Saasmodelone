# ADR 0004 — Statutory rules are versioned data, not model output

Status: accepted · October 2026

## Context

Payroll law is jurisdiction-specific. Contribution rates, tax bands, ceilings, eligibility tests, rounding rules, statutory reports and bank-file formats differ by country and often by subdivision. They change on published effective dates. A single global formula is wrong, and a plausible-sounding calculation generated by a language model is a liability rather than a feature. Errors cause underpayment, penalties and loss of trust.

The product must cover many jurisdictions without forking its core or pretending that one country's rules are the default.

## Decision

- Statutory rules are stored as **versioned packs scoped to a jurisdiction** (country or subdivision), with effective dates, source references, a qualified local reviewer's sign-off and a checksum.
- A payroll run may use more than one pack (for example national and subnational). It records the exact pack versions and input hash used.
- Application code implements deterministic calculation mechanics: gross-to-net, eligibility, ceilings, proration, rounding, arrears and adjustments. It does not hard-code rates or thresholds.
- Statutory reports and bank-file formats are pack-defined output adapters. A new jurisdiction adds reviewed data, adapters and tests; it does not fork the core.
- Golden test cases are maintained per pack with a qualified local payroll advisor, including mid-month joiners, exits, arrears, multiple employers, subnational rules and negative-net guards.
- A rule change requires a new pack version, tests, review and an audit event. A finalised run is never recalculated with a newer pack.
- AI may summarise a published rule, flag an anomaly or help draft a test case. It cannot author or approve a pack, calculate final liability or finalise payroll.
- No jurisdiction is claimed as supported until its pack has passed review and golden tests against representative cases.

## Consequences

- More upfront work and an ongoing local-review relationship for every covered jurisdiction.
- Rule changes are auditable, reproducible and historically accurate.
- The core schema and engine stay country-neutral; statutory content is local by design.
- Adding a jurisdiction is a content and validation programme, not a schema migration.
- This is the correct cost for a payroll product that expects to be trusted across borders.
